# QQ 被动回复窗口越界：长任务的完成通知会丢

> 状态：现行 ｜ 最后更新：2026-11-03
> 关联：`docs/manuals/bot-qq.md` §7、`src/main/java/.../builtin/qq/QqSender.java`、`QqApiClient.java`

## 1. 现象（线上）

2026-11-03 `$b` 地图备份：

| 时间 | 事件 |
|---|---|
| 10:48:42 | 管理员发 `$b`，前几条回执（地图目录 / 备份目录）正常送达（走被动回复） |
| 10:49 – 11:13 | `阶段:Running(ChunkProgress → Compress → Cleanup)`，5,061,518 单元，**25 分 01 秒** |
| 11:13:43 | `阶段:Done 进度:100%`（备份本身**完全正常**，无错误、无失败回调） |
| 11:13:55 | `[qq] 投递失败（HTTP 400，不重试）… {"code":40034005,"message":"回复消息msg_id已过期"}` |

用户视角：**备份跑完了，群里一句话都没有**（看起来像"命令没生效/没备份"）。

## 2. 根因（两层，缺一不可）

1. **通道语义错配**：`$b`/`$o` 的完成回执走的是入站消息的**被动回复**通道（带 `msg_id`，D14），
   而 QQ 被动回复窗口是 **群 5 分钟 / 单聊 60 分钟**——25 分钟的任务 100% 越窗。
2. **拒收兜底不全**：`QqSender` 只把 `40034128`（次数/时间超限）识别为"被动通道被拒 → 改主动重投"，
   平台对超窗实际返回的是 **`40034005`（msg_id 已过期）**，于是落到 `投递失败（HTTP 400，不重试）`
   **直接丢弃**——只留一条 WARN 日志，没有任何群内提示。

附带发现（同一盘点）：

- 序号表 `replySeq` 超限时整体 `clear()` → 仍在窗口内的 `msg_id` 的 `msg_seq` 从 1 重来 →
  平台判重 `40054005` 丢消息（概率低但确定）；
- `runExclusive` 互斥时**直接 return**：备份进行中再发 `$b`/`$o` 什么回执都收不到；
- `$b` 成功只走命令回执、失败反而额外走主动通知（`notifier.event`）——语义倒挂：**失败能看到、成功看不到**；
- 各 `runAsync` 分支 `catch` 只打日志不回复（`$l`/`$w` 异常时用户静默无响应）。

## 3. 修复（两层 + 业务层）

| 层 | 做法 | 位置 |
|---|---|---|
| 平台层①「发送前预判」 | 回执携带来源入站消息的**接收时刻**；窗口余量不足（群 >4 分钟 / 单聊 >59 分钟）→ **首发即主动消息**，不浪费一次注定失败的请求 | `QqReplySink.sendReply(..., receivedAt)` → `QqBuiltinAdapter` → `QqSender.planReply` |
| 平台层②「拒收兜底」 | `40034128` 与 `40034005` 统一视为「平台明确未投递」→ 主动消息重投一次（不会重复通知） | `QqApiClient.isPassiveReplyRejected` + `QqSender.send` |
| 平台层③「序号表」 | 按首次出现时间淘汰旧 `msg_id`，**不清空**（避免 `msg_seq` 重置被判重） | `QqSender.evictStaleReplyStates` |
| 业务层 | `$b`/`$o` 的**完成**通知改走主动群通知（`notifier.event`），与失败通知同构；定时备份仍只进日志 | `WorldMaintenanceService.progressHandler` |
| 业务层 | 忙碌时回执「已有备份/优化正在进行」；异步 `catch` 补一句失败回执；`$p`/`$v` 加 60s 总超时 | `runExclusive(busyWork)`、各 handler |
| 业务层 | `$w`/`$v l` 无页码参数时最多自动发 5 页（被动配额上限）+ 提示用 `$w <页码>`（避免几十页抽干主动消息配额） | `Paginator(maxPages, truncatedHint)` |

## 4. 复现与验收

- **单元**：`QqSenderTest`（`40034005` 兜底重投、超窗首发即主动、群/单聊窗口边界、窗口内仍被动）、
  `WorldMaintenanceServiceTest`（`notifyCompletion=true` → `notifier.event`；`false` → callback；
  忙碌 → 回执）、`PaginatorTest`（自动页数上限 + 提示）、`ScheduledBackupServiceTest`（定时备份仍不进群）。
- **真机**：触发一次 >5 分钟的 `$b`，预期日志出现
  `被动回复窗口已过（5 分钟…），改用主动消息发送` 或 `被动回复被平台拒绝（…改主动消息重投一次）`，
  且群里收到「地图备份 完成 用时:…」。

## 5. 经验（写进红线）

1. **任何"几十分钟后才回话"的功能，都不能挂在被动回复通道上**——要么业务层直接走主动通知，
   要么平台层按入站时刻预判降级。别指望靠错误码兜底：等你看到 `40034005` 时，消息已经丢了。
2. **错误码兜底要覆盖同一语义家族**（超限/超窗/`msg_id` 过期/无效），只认一个码等于没兜底。
3. **"没有回复"也是缺陷**：命令触发的异步链路，`catch` 里必须给用户一句失败回执；
   互斥跳过也必须回执，否则用户会连发同一命令。
