# 敏感信息事故处置与防护（SOP）

> 状态：现行 ｜ 最后更新：2026-09-13
> 适用：任何「私钥 / 凭据 / 平台密钥 / 真实用户标识」被提交并推送到远端的情况。

## 1. 红线（写入 AGENTS.md）

- **公开仓库**：本仓库是 public——任何入库内容都视为已公开。私钥/密钥/口令**一次都不能提交**。
- 需要凭据的场景（测试服、CI、发布）一律走：**环境变量 / 本地 `run/`（已 gitignore）/ GitHub Secrets**。
- 事故处置顺序：**先轮换密钥 → 再清 HEAD → 最后（可选）重写历史**。顺序颠倒毫无意义（历史里的密钥永久可用）。

## 3. 防护措施（已落地）

1. **`scripts/check-secrets.sh`**：扫描全部**已跟踪文件**中的高信号模式（私钥头、`ghp_`/`github_pat_`、`AKIA*`、`xox*`、`sk-*`、赋值式长密钥），命中即失败并给出处置指引；
2. **Gradle 门禁**：`checkSecrets` 任务已并入 `./gradlew check` → **CI（build workflow）与本地提交前门禁都会执行**；
3. **`.gitignore` 兜底**：`*.key`/`*.pem`/`id_ed25519*`/`.env`/`server.properties` 等，以及**以 `#`、引号、`*` 开头的文件名**（正是本次事故的文件名形态）；
4. **人工全历史排查**：`bash scripts/check-secrets.sh --all-history`（慢，用于周期性审计/事故复盘）。

## 4. 历史重写决策指引

删除 HEAD 中的文件**不会**把它从历史中移除（tag/旧提交仍可检出）。是否重写历史按下表判断：

| 情形 | 建议 |
|---|---|
| 密钥已轮换（旧密钥失效） | **不需要**重写历史（风险已归零；重写会打断所有 PR/克隆，成本远大于收益） |
| 凭据无法轮换（如平台不支持重置、真实用户标识/隐私数据） | 需要重写（`git filter-repo --invert-paths --path <file>`，随后 force-push 全部分支与 tag，并通知协作者重新克隆） |
| 仓库有 fork / 已被克隆 | 重写**无法**收回已分发副本 → 仍以「轮换」为唯一可靠手段 |

重写窗口需 owner 明确批准（本仓库规则禁止对 main/develop 强推，需临时豁免）。

## 5. 发现冲突时的优先级

1. 立刻轮换/吊销受影响的凭据（最优先，且只有 owner 能做）；
2. 删除 HEAD 中的文件并合入 main（hotfix）+ develop；
3. 补/更新门禁，避免同类复发；
4. 视情况重写历史；
5. 复盘写入本文件（新事故加一节，保留时间线）。
