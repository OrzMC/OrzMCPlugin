## 四、工具限制与操作要点（非插件缺陷，记录备查）

| # | 限制 / 要点 | 说明 |
|:--|:--|:--|
| L1 | mineflayer 不支持 transfer 协议包 | 收到 `transfer` 命令不会自动重连目标服（minecraft-protocol 未实现） |
| L2 | mineflayer 无法触发 PlayerPortalEvent | tp 被原版"吸入"拉到门口（y=64 地面）；跳跃碰撞箱进入 portal 区域（y=65+）也不触发；pathfinder 行走穿过不停留触发——**真实玩家验证是唯一可靠方式** |
| L3 | pathfinder 默认会挖方块 | `Movements` 默认 `canDig: true`，寻路时会破坏方块（实测挖了传送门前地面 sand）——**必须设 `mc.canDig = false`** |
| L4 | `/portal` 语法无 create 字面量 | `greedyString` 会把 "create" 吞进 target → `端口需为数字`；正确：`/portal <host> <port>` |
| L5 | 传送门目标 IP 必须玩家可达 | `127.0.0.1` 只对同机玩家有效（transfer 由客户端主动连接，127.0.0.1 = 玩家自己的机器 → Connection refused error -61）；局域网玩家填服务器局域网 IP |
| L6 | 传送门内部禁止放置方块 | setblock 垫块在框架内部会破坏结构判定 → portal 方块全部消失；重建需 remove 后重新 `/portal create` |
| L7 | 传送门坐标显示 | 创建消息"轴向:X"与 portals.yml 存储"Z"不一致——显示 bug，以存储为准 |

## 五、发现的 Bug 与修复

| 编号 | 现象 | 根因 | 修复 | 验证 |
|:--|:--|:--|:--|:--|
| BUG-01 | `debug $h` 模拟群发命令不可用 | 原版 `/debug` 命令抢占前缀（Incorrect argument）；改前缀报 Unknown（未注册命令不触发 ServerCommandEvent） | 前缀改 `orzdebug` + FeatureModule 注册命令 | PR #159，已实测 9 命令全过 |
| BUG-02 | `/portal create` 报「端口需为数字」 | `argument("target", greedyString())` 无 create 字面量，create 被吞进 target | 文档纠偏：正确用法 `/portal <host> <port>`（非代码缺陷） | 实测双服建门成功 |
| BUG-03 | 传送门创建消息轴向与实际存储不一致 | 显示 infoAxis 与存储 portalAxis 混淆 | 以 portals.yml 存储为准（显示 bug，暂不修） | 探测确认 |
